# Design polish component reference

This review artifact defines the proposed mobile shell and transaction-entry hierarchy before any production components change. The working HTML prototype is `design-reference.html` in this folder.

## Outcome

The app gains one persistent top control rail shared by Home, Budget, and Insights. The rail owns `Joint / Husband / Wife`, Search, and Date. The scope choices sit directly on the app background without an enclosing track. Search, Date, bottom navigation, and composer controls use a restrained Liquid Glass-inspired navigation layer. The existing three-tab navigation remains, while Add becomes a labeled action. Transaction history becomes date-grouped and the Add flow becomes an amount-first composer with its own keypad.

<Callout id="design-decision" tone="decision">

Scope and global actions are application chrome. They must be owned by `AppShell`, not repeated inside individual tab screens.

</Callout>

## Settled design decisions

- No mascot is introduced.
- The light visual system and current brand accent remain.
- The scope picker appears in the same top position on every tab.
- Search and Date sit to the right of scope and remain available app-wide.
- Glass is reserved for navigation and interactive controls; budget and transaction content remain on stable surfaces.
- Transaction rows retain the current codebase treatment: solid `surface` background, 14-point corners, no enclosing group border, and 6-point separation.
- Home, Budget, and Insights remain the three primary tabs.
- Add is a labeled pill inside the floating navigation surface.
- Activity is grouped by date and presented as flat two-line rows.
- The transaction composer follows this order: type, amount, description, pickers, keypad, confirmation.
- Date, category, and account pickers sit directly above the keypad.
- The final swipe control has a keyboard and tap alternative when implemented.

## Scope and non-goals

This proposal changes hierarchy, placement, and component styling. It does not change transaction APIs, account/category data shapes, navigation labels, the existing theme strategy, or budgeting calculations. Dark-mode refinement, advanced motion, and new mascots are deferred.

## Approval gate

Review the Home shell and transaction composer in the canvas, then use the standalone HTML for interaction. Production work begins only after the component placement and composer hierarchy are approved.
